## Optional canvas bucket for the deployment agent

The opt-in `enable_canvas_object_bucket = true` adds an S3 bucket with public access blocked, AES256 server-side encryption, HTTPS-only policy, protected destruction, and narrowly scoped EC2 permissions under `canvases/`. It adds a Standard SSM parameter `CANVAS_S3_BUCKET` and an output. It uses no KMS customer-managed key and does not enable S3 versioning. No automatic object expiration is configured because these are durable project documents. Empty buckets do not make the rest of the stack free.

Before enabling it, the operator must inspect the actual deployment's `CANVAS_S3_BUCKET`, `CANVAS_S3_PREFIX`, DynamoDB canvas pointers and current Terraform state. The IAM policy assumes the default prefix `canvases`; a custom prefix requires a deliberate policy change. If objects already live in another bucket, **do not switch the setting** until they have been migrated and their referenced keys and restore behavior verified. Changing a bucket name in configuration does not move existing objects. The backup gap above also needs a recovery solution before this becomes a durable production dependency.

If there is no existing S3 canvas data and the prerequisites are satisfied, set the opt-in variable, review `terraform plan` with the correct state and account, apply it, and provide the output as `CANVAS_S3_BUCKET` to the Node application process using its normal deployment mechanism. The optional SSM parameter can also be loaded with `dist/recovery/with-aws-env.cjs` when that helper launches the Node process. Ensure `AWS_REGION` matches. The parameter alone does not update an already running process. Enabling this bucket does not itself switch `CANVAS_DOC_MODEL` or migrate any canvas.

## Minimizing the existing fixed cost

The existing Cognito custom-sender flow encrypts codes with its customer-managed KMS key before queuing. Removing that key without redesigning the sender breaks verification; simply switching an S3 encryption setting cannot remove it. If eliminating the approximately $1/month key matters more than demonstrating custom queue-based verification, a future change could evaluate Cognito's built-in email delivery instead, then explicitly migrate and test the auth flow before retiring the custom sender, its encrypted queue consumers and KMS key. Do not remove or replace any live user pool, key, queue or state based only on this audit.

No Terraform apply, AWS credentials, live service tests, data migration, cost estimate using this account's real usage, or recovery drill was performed as part of this audit.
